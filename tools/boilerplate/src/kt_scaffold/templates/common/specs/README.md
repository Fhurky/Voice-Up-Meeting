# Specifications

Business work is domain-first and spec-driven.

1. Define the bounded context in specs/<domain>/DOMAIN.md.
2. Create one independently deliverable capability with kt-scaffold spec.
3. Review its PRD and set Status: Accepted.
4. Derive plan.md, then tasks.md.
5. Generate and implement schema, backend, frontend and browser evidence from that PRD path.

The delivery order is Spec → Plan → Tasks → Implement. A resource name alone never authorizes code.
